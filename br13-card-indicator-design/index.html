BR-13 Card Indicator: Design Options

The parent ticket locks BR-13's visual treatment as "TBD, in Design next." This page proposes and compares options for that one open item, then recommends a direction. Everything else in the parent ticket (the toggle lock, the modal reminders, the API carryover logic) is unchanged and out of scope here.

Rule recap
BR-12: when an API-initiated stage move happens while Drips are disabled at the Deal level, the disabled state carries over into the new stage instead of resetting to the sequence default.
BR-13: when that carryover happens, the Deal card needs a visual indicator so the next person to open the pipeline can see Drips were kept disabled automatically, without digging into the deal.
BR-14: the same carryover + indicator applies when the reason is Contact-level opt-out rather than a Deal-level toggle, and that reason takes precedence in the messaging (reuses the BR-2 copy: "This contact has opted out of all drips.").
Context
Where this shows up
Card anatomy below (header row, subtitle, content rows, divider, avatar/name/timestamp footer) is rebuilt from the actual Command Center card screenshots, not invented. The BR-13 pill is the only new element added to this existing structure.

Assumption to confirm
The ticket says the indicator must be visible "the next time a user views that card," but doesn't say whether it should disappear after that first view or persist. This design assumes the pill reflects current state: it shows as long as Drips remain disabled on that deal, and goes away on its own if Drips are re-enabled or a Contact-level opt-out is cleared, rather than being a one-time "new" flag a user dismisses. Flagging this for confirmation before build, since the ticket doesn't specify it.

Build notes
PropertyValue
PlacementInline on the card, directly under the subtitle line and above any job-specific content rows (Balance, Schedule, Crew, etc). Same slot regardless of how many content rows a given card has, so it's always found in the same place.
Visibility conditiondeal.dripsDisabled === true at render time (covers both the BR-12 deal-level and BR-14 contact-level cases, contact opt-out takes precedence per BR-14, so check contact opt-out first, then fall back to the deal toggle).
IconPause glyph (two vertical bars), 10×10px inside the pill.
ColorsBackground #E8E6FA, border #D6D2F5, text/icon #5C53DC, the same lavender tag/chip tokens already used for status badges elsewhere (design-system.md section 3), not a new color.
Label"Drips paused" (11px, 600 weight), always visible, no truncation at any card width.
Tap/click behaviorOpens a small popover anchored to the pill with the reason. Popover title + body text swaps based on cause (deal-level carryover vs. Contact-level opt-out, reusing the exact BR-2 string for the latter).
Does not affectMove / Change / Send Proposal / Approve Without Signature modal reminders: those are separate, already covered by BR-4 through BR-10. This pill is the passive, card-level signal for the no-user-present API path only.
