BR-13 Card Indicator: Design Options

The parent ticket locks BR-13's visual treatment as "TBD, in Design next." This page proposes and compares options for that one open item, then recommends a direction. Everything else in the parent ticket (the toggle lock, the modal reminders, the API carryover logic) is unchanged and out of scope here.

Rule recap
BR-12: when an API-initiated stage move happens while Drips are disabled at the Deal level, the disabled state carries over into the new stage instead of resetting to the sequence default.
BR-13: when that carryover happens, the Deal card needs a visual indicator so the next person to open the pipeline can see Drips were kept disabled automatically, without digging into the deal.
BR-14: the same carryover + indicator applies when the reason is Contact-level opt-out rather than a Deal-level toggle, and that reason takes precedence in the messaging (reuses the BR-2 copy: "This contact has opted out of all drips.").

Assumption to confirm
The ticket says the indicator must be visible "the next time a user views that card," but doesn't say whether it should disappear after that first view or persist. This design assumes the pill reflects current state: it shows as long as Drips remain disabled on that deal, and goes away on its own if Drips are re-enabled or a Contact-level opt-out is cleared, rather than being a one-time "new" flag a user dismisses. Flagging this for confirmation before build, since the ticket doesn't specify it.
