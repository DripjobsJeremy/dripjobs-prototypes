Notes for Jeremy
Assumptions and open gaps flagged during this build, per the "flag rather than guess" instruction
Assumption
Step 1's "No" branch is built exactly as your Phase 1 brief specified: a placeholder redirect to Company Settings. The Enhancement ticket's own text describes a more granular path ("indicate the Industry is wrong" → back into Step 2 selection) and separately flags that the address-only-wrong case is unresolved. I followed your brief's simpler version for this checkpoint — flag if you want the more granular branching built instead.
Assumption
The Industry-Change confirmation modal's copy is my own placeholder wording — no ticket specifies exact copy for it (only that it must warn Production Rate configuration could be affected and require confirmation). Treat the wording as a starting point, not final copy.
Assumption
Step 2 lets you reassign which selected Industry is Primary (a "Make Primary" action on any Additional industry) rather than permanently locking Primary to whatever was confirmed in Step 1. This wasn't explicitly specified either way, but it seemed necessary to actually demonstrate "select one as Primary and any number as Additional" as its own interaction.
Open Gap (carried from tickets)
What happens when only the Company Address is wrong (not the Industry) is explicitly flagged as unresolved in the First-Time Setup ticket. Not built here since no behavior is defined yet.
Open Gap (carried from tickets)
Duplicate-selection safeguard (selecting the same Industry as both Primary and Additional) and mid-wizard abandon/resume behavior are both flagged as unaddressed in the source ticket. Not built here.
Assumption (Phase 2)
"Areas" in the new hierarchy are the fixed top-level types (Interior/Exterior for Painting, Exterior for Gutter Services) per the Epic's own example ("Residential Painting: Interior → Walls → 8' Smooth Walls..."). This is a different concept from the old UI's per-room rows (Office, Kitchen, etc. seen in the reference screenshots) — those aren't mentioned anywhere in the five tickets, so I've treated them as a separate, unaffected Proposal Builder concept rather than guessing they belong in this new hierarchy.
Assumption (Phase 2)
Products are scoped per-Industry (each Industry has its own Product list) rather than one global list shared across Industries. Not explicitly specified either way, but a shared list would let a Gutter Services product surface for a Painting substrate, which conflicts with the isolation rule repeated throughout the tickets.
Open Gap (Phase 2)
Switching the Industry being viewed via the header switcher does not show the Industry-Change confirmation modal here — that modal is reserved for changing which Industries the account has (BR9/Section 11), not for browsing between Industries you've already set up. Flagging the distinction explicitly in case that's not how you pictured it.
